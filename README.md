# 建設労働者賃金の日次収集

災害後のデマンドサージ研究のため、求人ボックスの**公開検索結果および robots.txt で許可された公開求人詳細**から、建設現場系職種の賃金メタデータを日次で収集します。求人本文全体、応募情報、ログイン後情報、個人情報は保存しません。

## 実行方法

```bash
pip install -r requirements.txt
# 全47都道府県・全対象職種
python scraper.py
# 小規模な動作確認
python scraper.py --prefectures 東京都,大阪府,石川県
# 抽出候補タイトルと除外理由を出力して、取得件数を10件に制限した動作確認
python scraper.py --prefectures 熊本県 --occupations 大工 --max-rows 10 --debug
```

GitHub Actions は毎日 01:00 JST（前日 16:00 UTC）に実行されます。`workflow_dispatch` では、都道府県・職種をカンマ区切りで指定でき、動作確認用に最大取得件数も指定できます。スケジュール実行ではこれらの指定を省略して全件を収集します。`data/daily` に差分があれば `Update job wage data YYYY-MM-DD` で自動コミットし、実行中に他の変更が入った場合はリベースしてからプッシュします。

## アクセス方針

- 実行開始時に `robots.txt` を取得・解析し、取得に失敗した場合はフェイルクローズで処理を中止します。
- robots.txt 非許可 URL に加え、`/api/`、`/suggest/`、`/rd/`、`/map/`、`/my/`、`/apply*`、`/pdf/`、`/server-collect/`、`/jobreport` はコード上でも明示的に拒否します。
- ログイン、応募、マイページ、API、CAPTCHA・アクセス制限の回避は行いません。404 は再試行せず、それ以外の失敗は最大2回で打ち切ります。各 HTTP リクエストの前に最低3秒（標準4秒）待機します。
- `User-Agent` を明示し、検索 URL の `e=5,3,4` と `not:` による除外キーワードで、雇用形態と対象外職種を取得前から絞ります。robots.txt で許可された検索結果は次ページがなくなるまで取得します。詳細ページは勤務地・交通、給与・報酬、雇用形態、仕事内容を精度高く取得するため検索条件ごとに最大2件だけを取得します。
- JavaScript で静的 HTML から取得できない場合も、Playwright/Selenium による回避は実装しません。サイト運営者の許可を確認した上で、公式に提供される手段を検討してください。

## 保存データ

収集結果は日付ごとの `data/daily/jobs_wage_YYYY-MM-DD.csv` にのみ保存します。同日に再実行した場合は、同一の `job_url`、`scrape_date`、`query_occupation`、`prefecture` の組み合わせを二重保存しません。各ファイルは UTF-8 BOM付きCSVで、固定カラム順です。

| カラム | 内容 |
| --- | --- |
| `scrape_date`, `source_site`, `query_occupation`, `prefecture` | 取得日、ソース、検索職種・地域 |
| `job_title`, `company_name`, `location`, `job_url`, `search_url` | 公開求人の構造化メタデータ |
| `work_prefecture`, `city_ward`, `oaza_town`, `chome`, `ban`, `go` | 求人に明記された勤務地を分解した都道府県、市区町村、大字・町名、丁目、番地、号。`prefecture` は検索条件の都道府県 |
| `wage_text`, `wage_type`, `wage_min`, `wage_max`, `wage_unit` | 原文給与と、可能な範囲で正規化した円単位の給与 |
| `employment_type`, `posted_date_text` | 雇用形態、掲載・更新日原文 |
| `is_excluded_fulltime`, `is_disaster_related`, `notes` | 正社員・新卒の除外判定、災害関連語の検出フラグ、パース等のメモ |

対象は現場系・技能系の27職種グループです。各グループの通常公開検索 URL（`/{職種}の仕事-{都道府県}`）を取得し、職種の肯定語を含む求人だけを保存するため、表記ゆれを拾いつつグループ単位で分析できます。品出し、販売、営業、事務、施工管理、設計、運輸・物流、製造、サービス職などの除外語を含む求人は、保存前に除外します。詳細ページを取得した求人は、タイトル、企業名、雇用形態と「仕事内容」を使って同じ職種ルールを再適用します。「仕事内容」は判定のみに使用し、保存しません。正社員・新卒は検索条件で完全除外できないため `is_excluded_fulltime` を記録し、分析時に除外できます。`--max-rows` を指定した場合、職種・掲載日・詳細ページの再判定を通過した収集結果だけが上限件数に数えられます。

勤務地は詳細ページの「勤務地・交通」の住所行を優先します。駅名や所要時間、給与補足は保存せず、住所・給与は取得できた範囲だけを保存して補完・推測はしません。

`is_disaster_related` は、検索カードおよび取得を許可された詳細ページに「災害」「復興」「地震」「震災」「被災」「復旧」「台風」「豪雨」「洪水」「津波」「土砂災害」のいずれかが含まれる場合に `true` です。求人本文は保存しません。
